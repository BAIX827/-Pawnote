# 技术架构与平台决策
版本：0.1 · 2026-10-10

## ADR-001：从 Expo 通用工程开始
目标平台：先 iPhone，再 Android；首发市场为中国大陆。当前 Web 用于核心流程预览。
选择 Expo + React Native + TypeScript。Web 与移动端共享 UI、事件模型、成长规则和模板生成；图片、存储、分享由平台适配层处理。

开发顺序：需求与验收 → 通用工程 → Web 核心流程 → 早期真机检查 → 云端服务 → 好友社交 → 手机封闭测试 → 商店发布。
第一版发布到 Web 能快速反馈交互；原生相机、键盘、分享、权限和性能需要真机验证。真机检查安排在核心流程稳定后立即进行。

方案适配理由：当前功能主要是图片、表单、时间轴和卡片，React Native 能承载；同一领域模型可支持后续原生能力。
另一条可用路线：React Web + Capacitor 适合主要保留网页界面的混合应用，但本项目希望以移动体验为长期基础，因此选择 Expo。
微信小程序作为独立渠道，在用户来源和获客需求确认后评估；现阶段投入手机 App 工程。

## 原型结构
- src/app：Expo Router 文件路由与根布局。
- src/data/store.tsx：共享状态与持久化协调。
- src/domain：类型、模板引擎、成长与事件保存规则。
- src/data：本机持久化与示例数据。
- src/components / src/screens：跨端页面与 UI。
- src/platform：图片与卡片导出/分享。
- tests：成长、事件幂等、删除、模板事实引用与卡片转义验证。
- docs：需求、架构、计划和验收。

本地流程：UI → 领域函数 → 更新 State → Storage adapter。
联机流程：UI → Repository/API → 鉴权服务 → 数据库/对象存储。
生成流程：LifeEvent + PetSnapshot → StoryGenerator → Story variants。

## 后端目标（尚未接入）
基于用户确认的中国大陆市场，推荐国内部署的 TypeScript HTTP API + PostgreSQL + 对象存储。腾讯云优先评估，具体产品、区域与预算在开通服务前定案。
手机号验证码作为首个正式账号方案的建议；短信、身份令牌和访问控制由服务端处理。CloudBase 身份认证等托管能力可评估，通过 HTTP API 与 React Native 对接，先验证兼容性。
国内可用的生成模型通过服务端 Provider adapter 接入；原型模板继续作为回退。
服务端 TypeScript 实现鉴权、事件保存事务、审核、成长与生成；前端模型密钥为零。
AI 生成接服务端 HTTP 接口，模板作为稳定回退；对输入/输出做约束和审核，记录 provider / model / promptVersion / sourceEventId。

## 移动端发布路径
1. 核心代码通过 Web 测试与 native bundle 导出。
2. Expo Go 或 development build 检查相机、存储、键盘和安全区域；原生依赖需要时采用 development build。
3. 确定应用标识、开发者账号、签名与隐私文案后配置 EAS。
4. 先完成 iPhone development build 与 TestFlight，随后 Android 内测，检查真实网络和权限。
5. 完成数据删除、审核响应、内容标识、隐私披露和商店资料后提交审核。

原型静态 Web 可以通过 Sites 预览；它与正式云端 API 的部署生命周期分开。

## ADR-004：AI 生成网关与双地区服务商（2026-10-11）
用户确认 AI 生成与本机规则并存、国内外同步。决策：
- 新增独立的 AI 网关（仓库 server/，Node 22，无第三方依赖）。客户端只知道网关地址，模型密钥只存在于网关环境变量。
- 网关按请求里的地区选择服务商：cn → DeepSeek（OpenAI 兼容接口，默认模型 deepseek-flash，可用环境变量改）；intl → 任意 OpenAI 兼容服务，由 INTL_BASE_URL / INTL_API_KEY / INTL_MODEL 配置，未配置时回落到 cn。
- 客户端地区来自构建变量 EXPO_PUBLIC_REGION（cn 或 intl，默认 cn）；网关地址来自 EXPO_PUBLIC_API_URL，未设置时 App 只提供本机规则生成。
- 次数在网关侧按设备标识与自然周（周一 UTC 重置）统计，非会员每周 2 次（FREE_AI_PER_WEEK）。当前没有账号体系，设备标识由客户端生成并保存在本机，可被重置；接入登录后改为按账号统计。
- 会员身份暂由网关环境变量 MEMBER_DEVICE_IDS 配置，订阅接入后替换为订阅校验。
- 当前用量保存在网关本地文件，仅适合单实例试运行；正式部署改用数据库。
- 国内正式访问需要大陆可达的部署与备案，部署位置待定。


## ADR-005：网页版用 GitHub Pages 自动部署（2026-10-11）
- 网页版即 Expo 的 Web 导出（expo export -p web），与 iOS/Android 同源。
- .github/workflows/pages.yml 在每次推送 main 时运行类型检查与测试、导出并发布到 GitHub Pages，地址为 https://baix827.github.io/-Pawnote/。
- 站点位于子路径，导出时通过环境变量 EXPO_BASE_URL=/-Pawnote 注入 experiments.baseUrl（见 app.config.js）；本地开发与其他托管不设该变量，仍从根路径提供。
- 单页应用在 Pages 上刷新子路由会 404，部署时把 index.html 复制为 404.html 作为回退。
- CI 不设置 EXPO_PUBLIC_API_URL，网页版不显示 AI 入口。
- 前提：仓库需启用 Pages（来源选 GitHub Actions）。私有仓库启用 Pages 需要付费的 GitHub 方案，否则需将仓库设为公开；由仓库所有者决定。

## ADR-006：Mac 本地版（2026-10-11）
- 来源：用户要求先在自己的 Mac 安装爪记，并使用选定的黑白爪印图标。
- 复用 Expo Web 导出，以系统 AppKit / WKWebView 加载随 App 打包的资源。Mac 宿主代码独立放在 `macos/`，构建脚本放在 `scripts/`，移动端继续沿用 Expo Router 和原有模块。
- 内置仅绑定 `127.0.0.1` 的静态服务，固定端口 47831，以稳定的 origin 保持 WebKit localStorage。文件选择和下载通过系统文件面板处理；默认 WebKit 数据空间按 App 标识独立持久化。
- 当前是本机 ad-hoc 签名的 Apple Silicon App，安装到个人 `~/Applications`。公开分发的签名和公证由后续发布流程处理。运行检查使用独立临时数据空间和端口 47832。

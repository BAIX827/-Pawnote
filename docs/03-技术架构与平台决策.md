# 技术架构与平台决策
版本：0.1 · 2026-10-10

## ADR-001：从 Expo 通用工程开始
目标平台：最终 iOS / Android；当前 Web 优先验证。
选择 Expo + React Native + TypeScript。Web 与移动端共享 UI、事件模型、成长规则和模板生成；图片、存储、分享由平台适配层处理。

开发顺序：需求与验收 → 通用工程 → Web 核心流程 → 早期真机检查 → 云端服务 → 好友社交 → 手机封闭测试 → 商店发布。
第一版发布到 Web 能快速反馈交互；原生相机、键盘、分享、权限和性能需要真机验证。真机检查安排在核心流程稳定后立即进行。

方案适配理由：当前功能主要是图片、表单、时间轴和卡片，React Native 能承载；同一领域模型可支持后续原生能力。
另一条可用路线：React Web + Capacitor 适合主要保留网页界面的混合应用，但本项目希望以移动体验为长期基础，因此选择 Expo。
微信小程序作为独立渠道，在用户来源和获客需求确认后评估；现阶段投入手机 App 工程。

## 原型结构
- src/app：Expo Router 文件路由与根布局。
- src/data/store.tsx：共享状态与持久化协调。
- src/domain：类型、模板引擎、成长与事件保存规则。
- src/data：本机持久化与示例数据。
- src/components / src/screens：跨端页面与 UI。
- src/platform：图片与卡片导出/分享。
- tests：成长、事件幂等、删除、模板事实引用与卡片转义验证。
- docs：需求、架构、计划和验收。

本地流程：UI → 领域函数 → 更新 State → Storage adapter。
联机流程：UI → Repository/API → 鉴权服务 → 数据库/对象存储。
生成流程：LifeEvent + PetSnapshot → StoryGenerator → Story variants。

## 后端目标（尚未接入）
推荐托管 PostgreSQL、账号认证和对象存储作为首个后端，例如 Supabase；在首发市场、网络可达性与数据位置确认后定案。
服务端 TypeScript 实现鉴权、事件保存事务、审核、成长与生成；前端模型密钥为零。
AI 生成接服务端 HTTP 接口，模板作为稳定回退；对输入/输出做约束和审核，记录 provider / model / promptVersion / sourceEventId。

## 移动端发布路径
1. 核心代码通过 Web 测试与 native bundle 导出。
2. Expo Go 或 development build 检查相机、存储、键盘和安全区域；原生依赖需要时采用 development build。
3. 确定应用标识、开发者账号、签名与隐私文案后配置 EAS。
4. iOS TestFlight 与 Android 内测，检查真实网络和权限。
5. 完成数据删除、审核响应、内容标识、隐私披露和商店资料后提交审核。

原型静态 Web 可以通过 Sites 预览；它与正式云端 API 的部署生命周期分开。
